## Lab Work

This repository contains the laboratory submissions completed as part of the Software Engineering Laboratory course.

### Lab 1 — Requirements Engineering & UML Use-Case Modelling

**Topic:** Hostel Maintenance & Issue Ticketing System

Lab 1 covers:

* Functional and non-functional requirements
* Stakeholders and actors
* Requirement prioritization
* Acceptance criteria
* UML use-case modelling
* Use-case flow specification

[View Lab 1](./PES1UG24AM922_SELab1.PDF)

### Lab 2 — Agile Backlog Creation & Sprint Simulation in Jira

Lab 2 converts the functional requirements from Lab 1 into an Agile backlog using Jira.

It covers:

* Epic creation
* User story creation
* Backlog prioritization
* Fibonacci-based story point estimation
* Planning Poker
* Sprint planning and simulation
* Sprint board and task progression
* Burndown chart analysis

[View Lab 2](./PES1UG24AM922_Lab2_SELab.pdf)

### Lab 3 — Component Modelling & Architectural Pattern Selection

Lab 3 focuses on evaluating architectural styles and designing a UML Component Diagram for a self-service coffee kiosk.

It covers:

* Comparison of Layered, Microservices, and Client-Server architectures
* Selection and justification of a suitable architectural style
* Identification of system components and their responsibilities
* UML Component Diagram modelling
* Provided and required interfaces
* Component dependencies and data flow
* Security and performance considerations
* Architectural decision documentation

[View Lab 3](./PES1UG24AM922_SELab3.pdf)

### Lab 4 — Game Development & Feature Implementation using Pygame

Lab 4 focuses on developing and extending a Coin Collector game using Python and Pygame.

It covers:

* Implementing coin collection and preventing duplicate scoring
* Introducing multiple coin types with different point values and colors
* Implementing obstacles and player collision detection
* Managing player lives and handling collision consequences
* Implementing a 30-second countdown timer
* Handling round completion and displaying the final score
* Implementing a restart mechanism to reset the game state

[View Lab 4](./PES1UG24AM922_SELab4_06_coin_collector/)

### Lab 5 — Static Code Analysis

Lab 5 focuses on identifying and fixing code quality, style, and security issues using Pylint, Flake8, and Bandit.

It covers:

- Static code analysis using Pylint, Flake8, and Bandit
- Identifying code quality and style issues
- Detecting potential security vulnerabilities
- Documenting issues based on severity and type
- Fixing code quality and security issues
- Improving readability, maintainability, and coding standards
- Rerunning analysis tools to verify fixes
- Reflecting on static analysis findings and improvements

[View Lab 5](./PES1UG24AM922_SELab5_HostelAllocator/)

### Lab 6 — Code and Branch Coverage Analysis

Lab 6 focuses on measuring and improving test coverage using Python's `coverage` library and `pytest`.

It covers:

* Understanding line coverage and branch coverage
* Writing test cases using `pytest`
* Measuring code coverage using the Coverage.py tool
* Identifying untested statements and decision branches
* Testing edge cases and conditional paths
* Achieving more than 90% line and branch coverage

[View Lab 6](./PES1UG24AM922_SELab6/)

### Lab 7 — Fuzz Testing for Input Validation Bugs

Lab 7 focuses on identifying and fixing input validation bugs using property-based fuzz testing with the Hypothesis library.

It covers:

* Understanding fuzz testing and property-based testing
* Using Hypothesis strategies to generate unexpected inputs
* Testing input validation for PNR, journey distance, and berth type functions
* Identifying crashes and edge-case bugs
* Implementing defensive input validation
* Verifying application robustness using automated fuzz tests

[View Lab 7](./PES1UG24AM922_SELab7/)
